#+title: Companion Notebook

* Objective
Read and write without losing context or compromising native handwriting.

* Accepted requirements (2026-09-21)
- Portrait-first bottom pull-out writable margin overlays the main document.
- Main viewport and page scale do not shrink as the margin is pulled.
- Dragging updates the actual margin continuously, with no settle-on-release substitute.
- Two independently scrollable documents; write directly in either visible pane.
- Pull out the notebook and start writing without an activation tap. Native pen
  hit-testing chooses the document at stroke start and keeps it until pen-up.
- Toolbar context follows the pane in use; finger tap can choose toolbar context,
  but must not be required before writing. Scrolling does not change that context.
- Pairings belong to the primary notebook or PDF; no same-document pair in v1.
- Tucking preserves positions and pairing; detaching never deletes documents.
- No layout/focus/document changes during a stroke; gestures keep their owner.
- Prototype is local/offline. Native ink must use native controllers and saves.
- Pro only initially; no changes to Move or shared servers.

* Requirements changed
- Earlier proposal displaced/resized the main viewport: replaced by slide-over.
- Earlier automatic focus was replaced by explicit tap-to-select; on 2026-09-22
  the user superseded that decision again: direct writing in either visible pane
  is preferred, particularly after pulling out the notebook. No select-only pen tap.
- Same-notebook different locations: excluded from v1.
- Landscape in v1: deferred. Later landscape should fit scaled documents to equal halves.
- Divider-only preview fallback: rejected; live fluid movement is a hard gate.
- Design-only phase: user authorized implementation, with original device safety constraints.
- After the structural trial, the user explicitly requested continued work until
  usable unless technically infeasible or very risky. This supersedes the earlier
  overnight stop decision; it does not authorize unsafe pen routing or firmware edits.

* Validation and release decision
- Desktop controller and QML tests must pass, including pointer drag before release.
- Hardware must prove independent rendering, clipping, pen ownership and native durability.
- Base 3.29 XOVI/QRR qualification precedes any native probe.
- Any lost, duplicate or wrong-document ink blocks release.
- Measure high-speed-video drag latency and visual artifacts on the Pro; compare
  with stock touch response and obtain actual user acceptance of fluidity.
- No claim of native support or inclusion in reinstalls before these gates pass.
